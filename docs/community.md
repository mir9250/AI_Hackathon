# 돌려받집 커뮤니티

`mountCommunity(root, supabase)`는 기존 로그인 세션으로 Supabase Data API에 접속합니다. 게시글과 댓글은 로그인한 회원들이 함께 조회하며, 작성자만 자신의 글·댓글을 삭제할 수 있습니다. 게시글 삭제 시 연결된 댓글도 삭제됩니다. 익명 로그인 및 미로그인 접근은 허용하지 않습니다.

## 저장 및 권한

- 별도 `community_posts`, `community_comments` 테이블만 사용합니다. 기존 사진·주택·계약서·프로필 테이블을 공개하지 않습니다.
- 작성자와 작성 시각은 DB 기본값으로 설정합니다. 클라이언트에는 본문 등 지정된 컬럼만 INSERT 권한이 있어 작성자·시각 위조 및 UPDATE는 거부됩니다.
- 표시 이름은 ‘이웃의 이야기 / 이웃의 댓글’입니다. 이메일·주소·프로필을 조회하거나 표시하지 않습니다. 소유권 확인을 위한 사용자 UUID는 로그인한 회원이 읽을 수 있습니다.
- 제목 120자, 게시글 5,000자, 댓글 2,000자 제한을 UI와 DB에 적용합니다. 빈 공백만 있는 글은 DB가 거절합니다.
- 글은 20개씩 페이지 조회합니다. 댓글은 글마다 먼저 작성된 100개까지 표시하며 제한에 도달하면 안내합니다.
- 내용은 textContent로 렌더링합니다. 글·댓글에 HTML이 있어도 실행되지 않습니다.
- 자동 게시물 검수·신고·서버 요청 횟수 제한은 이번 범위에 포함하지 않습니다.

## 적용 상태

`supabase/migrations/20261115175657_community_posts_comments.sql`은 CLI로 생성했습니다. 스키마 SQL은 로컬 PGlite에서 검증했으며 실제 Supabase DB에는 아직 적용하지 않았습니다. 적용 전에는 ‘커뮤니티 저장소가 아직 준비되지 않았습니다’ 메시지를 표시하며 브라우저 임시 저장을 실제 공유 커뮤니티처럼 사용하지 않습니다. 운영 적용 후 두 실제 계정에서 작성·댓글·재조회·소유자 삭제 권한을 확인해야 합니다. SQL 적용과 프론트 배포가 모두 필요합니다.

## 검증

`node --test frontend/tests/community.test.mjs`

PGlite에서 SQL 전체 실행, 다른 회원의 읽기 및 댓글 작성, 타인 글·댓글 삭제 거부, 작성자 위조 거부, UPDATE 거부, 빈 내용·길이 제한, 글 삭제 시 댓글 제거, 미로그인 조회 거부를 확인합니다. jsdom으로 XSS 문자열의 안전한 표시와 cleanup을 확인합니다. 로컬 테스트는 실제 Supabase Auth·Data API 배포 검증을 대체하지 않습니다.
