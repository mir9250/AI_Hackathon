- 프론트·임베디드 DB 24개 테스트 통과, Vite 배포 빌드 성공.
- Uvicorn Health·Vite HTML 모두 HTTP 200, 테스트 프로세스 종료 완료. 외부 서비스 요청 없음.
- 정상 PNG/JPEG/WEBP/HEIC 실제 디코딩, HEIC JPEG 생성, 원본 바이트 보존, 파일 크기·형식·손상·해상도·위치·UUID 검증, 인증·주택 필수, 업로드 ID 재사용, DB 기록 및 목록, 타 사용자 목록 분리, 저장 실패 정리·정리 실패 로그, 동시 UNIQUE 충돌 모의 응답, DB 커밋 후 타임아웃 및 확인 실패 시 원본 보존을 검사했다.
- 화면은 jsdom에서 주택 등록 후 진입, 파일별 성공·실패, 같은 ID 재시도, 최대 10장·크기·위치 검사, 재마운트 후 저장 목록 조회, 로그아웃 시 사진 화면 제거, multipart JWT 전송을 확인했다.
- Supabase HTTP는 mock transport이고 실제 사진 업로드·삭제·DB 삽입은 수행하지 않았다. 실제 Supabase 계정에서의 사진 RLS·Storage signed URL·실기기 HEIC·브라우저 레이아웃은 미검증이다. 기존 Auth·프로필·주택 실연동은 사용자가 정상 확인했다고 보고했다.
- SQL·RLS·버킷 설정 변경 없음. 사진 실연동은 사용자 승인 후 기존 계정·가상 사진으로 진행해야 한다. 자세한 절차는 [입실 사진 안내](move-in-photos.md)를 참고한다.
- Python 3.14.5에서 검증했다. 고정 배포 기준 Python 3.13.9 검증과 Render 배포는 미실행이다. 기존 Starlette/AnyIO 경고 1건은 그대로다.

## Supabase 프로젝트 생성 후 재점검 (2026-11-14)

- 기존 마이그레이션·인증·프로필·주택 코드는 유지했다. 실제 Supabase에는 SQL·설정·데이터 변경을 수행하지 않았다.
- 양쪽 `.env`는 존재하지만 프로젝트 URL·키는 예시값이었다. 값 자체는 출력하지 않았다.
- 오프라인 설정 점검 도구와 연결 안내를 추가했다. 설정 점검 도구의 관리자 키 탐지·값 비노출 검증을 포함해 백엔드 51개 테스트, 프론트·DB 19개 테스트가 통과했다. 프론트 빌드도 성공했다.
- 설정 점검 명령은 미입력된 필드를 보고하고 예상대로 실패했다. 이는 실제 Supabase 장애를 의미하지 않는다.
- 로컬 기동 검사의 첫 시도는 샌드박스 포트 바인딩 제한으로 차단되었다. 허용된 재실행에서 Uvicorn·Vite 모두 HTTP 200을 확인했고 프로세스 종료도 완료했다. 외부 호출은 없었다. 아래 실행 결과는 이전 검증 기록이다.

검증일: 2026-11-14 (한국 시간). 외부 Supabase 프로젝트, OpenAI, Render, GitHub에 대한 실연동 동작은 수행하지 않았다. 개발 패키지는 PyPI·npm 및 Node.js 공식 배포처에서 설치했다.

## 실행 결과

백엔드 테스트는 토큰 누락·만료·발급자·audience·role·익명 사용자·위조 서명 모의 Auth 검증, 이메일 확인 상태, 검증된 사용자 ID, 프로필·주택 등록·조회·수정·사용자 분리, 401/403/409/422/5xx 오류, 연결 타임아웃, CORS preflight, 설정 오류의 비밀값 미노출을 확인한다.

프론트 테스트는 최신 세션 토큰 첨부, 오류·재시도 정보, 사용자 입력 HTML escaping, 한국 시간 표시, 로그인 후 조회·두 폼 저장·재로그인 후 재조회, 이메일 확인 필요 안내, 세션 복원·갱신·로그아웃 후 개인정보 화면 제거, 설정 누락 안내를 확인한다. 테스트 중 잘못된 UI 검증 선택자를 수정한 후 전체를 재실행해 통과했다.

DB 테스트는 PGlite 임베디드 PostgreSQL에서 실제 마이그레이션 SQL을 실행한다. 9개 테이블, RLS, 본인 프로필 upsert, 다른 사용자 읽기·쓰기 차단, 사용자당 주택 1개, 주택 ID 보존, 사진 연결·동일 주택·입실 stage·중복 업로드 ID, 계약서 페이지 중복·연속 번호·완료 조건을 확인한다. 별도로 PostgreSQL SQL 파서 검사도 수행했다.

실제 기동 검사는 테스트용 가짜 연결 설정을 사용하고 Health와 HTML만 요청한다. 개발 서버가 기동했다는 결과를 실제 서비스 데이터 연동 성공으로 해석하지 않는다. 최초 포트 바인딩은 샌드박스 제한으로 차단되었으며, 허용된 별도 실행에서 정상 기동·응답·종료를 확인했다.

## 환경과 남은 검증

- 실행 환경: macOS arm64, Python 3.14.5, Node.js 22.16.0. 배포 기준으로 고정한 Python 3.13.9에서는 아직 실행하지 않았다.
- 백엔드 테스트에 Starlette/AnyIO 내부의 deprecated alias 경고 1건이 있다. 테스트 실패는 없다.
- 실제 Supabase 마이그레이션 적용, Auth 토큰 검증, 실제 회원가입·이메일 발송·로그인·세션 갱신, PostgREST upsert, Storage 버킷 동작은 미검증이다. HTTP Auth 검증과 DB 쿼리는 모의 transport 및 로컬 DB로 검증했다.
- 브라우저 시각 검수·모바일 실기기 검증은 하지 않았다. jsdom은 레이아웃 엔진이나 실제 브라우저 보안·네트워크 환경을 대체하지 않는다.
- OpenAI 호출·실제 사진/PDF 업로드·계약서 삭제·Render 배포·유휴 복귀·서버 재시작 후 외부 저장소 보존은 후속 단계의 구현·승인·실연동 검증이 필요하다.
- 작업 중 기동한 서버는 모두 종료했다. 실제 키가 들어간 `.env`는 생성하지 않았다.

현재 상태는 **1·2단계의 로컬 검증 완료**이며, 전체 명세서 구현 완료나 외부 서비스 정상 작동을 의미하지 않는다. 사용자 직접 실행 확인 후 다음 단계 지시를 기다린다.
