# 돌려받집 — AI 보증금 기록 도우미

사진 관찰 → 특약 확인 → 입주/퇴실 비교 → 공제 근거 확인 요청을 연결하는 로컬 웹 앱입니다. **실제 OpenAI Responses API 호출 코드**를 사용하며 키가 없거나 호출에 실패하면 결과를 만들어 보여주지 않습니다.

## 실행

Python 3.9 이상, 외부 Python/Node 패키지 설치 없이 실행합니다.

1. `rental-demo/.env.example`을 같은 폴더의 `.env`로 복사합니다.
2. `.env`의 `OPENAI_API_KEY=` 뒤에 본인의 키를 넣습니다. 키를 채팅이나 GitHub에 올리지 마세요.
3. 프로젝트 루트에서 실행합니다.

```bash
python3 rental-demo/server.py
```

**http://localhost:8001/** 접속. API 키를 설정하지 않아도 기록·로컬 특약 키워드·수동 비교·리포트는 사용할 수 있습니다. 키 변경 후 서버를 재실행하세요. 계정의 모델 접근 권한과 사용 가능 잔액은 별도로 필요합니다.

- 기본 모델: `gpt-4.1-mini`. 서버 환경 변수 `OPENAI_MODEL`로 이미지 입력과 Structured Outputs를 지원하는 모델을 지정할 수 있습니다.
- 포트 변경: `.env`의 `PORT`. 기본값은 8001입니다.
- `python3 실험용.py`도 같은 전용 서버를 실행하는 호환 진입점입니다. 별도 정적 서버에서는 AI API가 동작하지 않습니다.

## 실제 AI 기능

| 화면 | 전송 자료 | 결과 |
| --- | --- | --- |
| 입주/퇴실 기록 | 선택한 사진 1장, 해당 공간의 메모 | 한국어 상태 태그·관찰 위치·하자 후보·추가 촬영 질문 |
| 특약 | 입력한 텍스트 | 원문 인용·불명확한 범위·확인 질문 |
| 전후 비교 | 입주 사진, 퇴실 사진 순서로 2장 및 메모 | 기존 흔적 가능·새 변화 가능·판단 보류 |
| 대응 문장 | 공제 항목·금액 및 저장된 입주 메모 | 중립적인 공제 내역 확인 요청 초안 |

AI 전송 전에 각 패널에서 전송 범위를 확인하고 동의 체크 후 버튼을 눌러야 합니다. 사진과 텍스트는 로컬 서버를 거쳐 **OpenAI**로 전송되며 API 사용료가 발생할 수 있습니다. 얼굴·주소·계약 당사자 식별정보는 먼저 가려 주세요. 체크박스 동의 없이 서버에 직접 요청해도 거절합니다.

실제 사진이 없으면 사진 분석 버튼을 사용할 수 없습니다. 예시 도식을 실제 분석에 보내지 않습니다. 실패·타임아웃·거절·형식 오류를 표시하며 자동 재시도하지 않습니다. 입력이 바뀌면 이전 응답임을 표시합니다. ‘관찰 명확성’은 모델의 설명이며 검증된 정확도나 확률이 아닙니다.

## 로컬 기기 저장과 리포트

이 절은 로컬 Python 서버 기준입니다. 배포 사이트는 로그인 후 계정별 DB·사진 저장을 지원하며 [배포 안내](../DEPLOYMENT.md)를 확인하세요.

- IndexedDB에 사진·메모·특약·AI 응답을 보관합니다. 새로고침 후 같은 브라우저와 같은 주소에서 복원합니다.
- 저장 오류는 화면 상단에 표시합니다. 중요한 자료는 사진 원본과 HTML 리포트로 따로 보관하세요.
- 로컬 Python 서버는 사용자 자료를 디스크에 저장하지 않으며 요청 본문·사진·키를 로그에 출력하지 않습니다. API 요청에는 `store: false`를 지정하지만 이는 제공자의 모든 데이터 처리·보관 정책을 대신하는 약속이 아닙니다.
- 브라우저 사이트 데이터 삭제, 시크릿 창 종료, 다른 기기/포트로 접속하면 동일한 기록을 복원하지 못할 수 있습니다.
- HTML 리포트에는 저장한 사진·메모·기기 등록 시각과 AI 참고 기록이 포함됩니다. 브라우저에서 열어 인쇄/PDF 저장할 수 있습니다.
- 사진은 공간별·입주/퇴실별 1장, JPG/PNG/WEBP 8MB 이하입니다.

## 법률·이미지 분석 한계

하자 원인·발생 시점·통상 마모·배상 책임·수리비·보증금 반환을 자동 확정하지 않습니다. 사진의 정렬도 자동으로 수행하지 않습니다. 기록의 기기 등록 시각은 촬영 시각이나 공인 인증 시각이 아닙니다. 샘플은 직접 만든 도식과 예시 메모입니다.

특약 인용은 입력 원문에 실제로 포함되는지 서버에서 확인합니다. 현재는 법령 검색/RAG가 없으므로 판례·법 조항 근거를 자동 생성하지 않습니다. [대한법률구조공단 임대차분쟁조정위원회](https://www.hldcc.or.kr/)의 공식 안내·관련 법령·서식으로 연결합니다. 외부 메시지 전송·조정 신청은 하지 않습니다.

## API 및 운영 범위

- `GET /api/health`: 키 설정 여부와 모델명. 키 원문은 반환하지 않습니다.
- `POST /api/analyze`: `task`, `area`, `text`, `images`, `consent`. 작업은 photo/compare/contract/draft.
- 서버는 127.0.0.1에만 바인딩하며 같은 Origin과 로컬 Host를 확인합니다. 요청 본문 24MB, 이미지당 8MB, 텍스트 16,000자 제한, 동시 요청 2개·분당 12개 제한이 있습니다.
- 정적 파일은 명시한 목록만 제공하며 `.env`, 서버 소스, 임의 디렉터리를 제공하지 않습니다.
- **로컬 개발용**입니다. 인터넷 공개 전에는 인증·사용자별 권한·요청 한도·서비스 배포 구성이 필요합니다. 정적 호스팅만으로 실제 AI API가 실행되지는 않습니다.

## 사진 태그 사용

1. 입주/퇴실 기록에서 공간과 입주/퇴실 구분을 선택합니다.
2. JPG/PNG/WEBP 사진(8MB 이하)을 등록하고 필요하면 메모를 입력합니다.
3. 사진 아래의 AI 분석 영역에서 전송 동의를 체크하고 분석 버튼을 누릅니다.
4. 결과의 **AI 상태 태그**와 관찰 근거를 확인합니다. 예: `#긁힘`, `#얼룩`, `#균열`.
5. 공간 기록을 저장한 뒤 리포트를 내려받으면 AI 태그도 포함됩니다.

`tags`는 `analysis.tags` 문자열 배열로 반환됩니다. 허용 태그는 긁힘, 찍힘, 균열, 들뜸, 변색, 얼룩, 곰팡이 의심, 물자국, 녹, 파손, 판단 보류이며 중복 없이 최대 6개입니다. 빈 배열은 눈에 띄는 흔적을 찾지 못했다는 뜻이며 하자가 없음을 보장하지 않습니다. 사진 이외 분석에는 빈 배열을 요청합니다. 이전 버전에서 저장한 태그 없는 응답도 계속 열 수 있습니다. 입력 사진·메모가 바뀌면 기존 결과에 이전 자료라는 안내가 표시됩니다.

기존 서버가 키 보관·동일 출처 API·요청 제한을 제공하므로 별도 FastAPI 서버나 패키지를 추가하지 않았습니다. 브라우저는 `/api/analyze`로 사진 data URL을 보내고, Python 서버만 OpenAI Responses API를 호출합니다. 정적 GitHub Pages에서는 이 서버가 실행되지 않습니다.

팀 작업과 main 반영은 [AGENTS.md](../AGENTS.md)의 공통 규칙을 따릅니다.

실제 연결 확인: 서버를 실행하고 `/api/health`의 `configured`가 true인지 확인한 뒤 위 화면에서 사진을 분석합니다. 키 누락(503), 잘못된 파일(400), 잘못된 키/모델 접근·잔액 부족, 네트워크 지연은 오류 안내로 표시하며 가짜 태그로 대체하지 않습니다. 실제 사진·유효한 키가 필요한 유료 호출과 실제 카메라 동작은 별도 확인해야 합니다.

사진 업로드 바로 아래에 AI 분석 영역을 표시합니다. 업로드·공간 변경·기록 저장 때 다시 표시하며, 실제 사진이 있으면 ‘AI로 문제 확인하기’ 버튼으로 시작합니다. 자동 전송은 하지 않고 동의 후 실행합니다. API 키가 없을 때도 버튼은 표시하되 설정 미완료 사유를 안내합니다.

### 저장된 기록 · 생활 일지

- #archive: 공간별 최신 입주·퇴실 기록, 생활 일지, AI 결과를 유형/검색어로 모아보기. 전체 사진 버전 이력은 아님.
- #journal: 날짜·제목·분류·공간·진행 상태·내용 작성 및 수정. 최대 100개, 제목 80자, 내용 2,000자. 임시 작성 내용과 완료된 일지는 구분.
- 로그인한 사용자의 일지와 임시 작성 내용은 기존 D1 workspaces.payload에 계정별 저장. 비회원은 기기 저장. 같은 계정으로 다른 브라우저에 로그인하면 복원. 기존 버전 충돌 보호 유지.
- HTML 리포트에 저장 완료한 일지도 포함. 발생일/예정일은 사용자 입력이며 시각을 인증하는 기록은 아님.
- 검증: records-test.cjs와 배포 소스 account-test.mjs, cloud-client-test.mjs로 작성/수정/검색, DB 왕복, 기기간 복원 및 계정 분리 확인. 실제 브라우저 시각 검수는 이 환경에서 미실행.
